=====================================================================
  МОСТ ДЛЯ TELEGRAM (когда основной сервер в России)
=====================================================================

ЗАЧЕМ
  С российских серверов Telegram заблокирован: бот пишет
  «Request timeout error». Нужен «мост» — через него идут ТОЛЬКО запросы
  к Telegram. Сервис, базы салонов и MAX остаются на российском сервере.
  Задержка +30–80 мс — клиенты не заметят.

  Два способа — нужен ОДИН:
    А. Cloudflare Workers — бесплатно, без второго сервера, 5 минут.  ← проще
    Б. Свой зарубежный сервер + SSH (если Cloudflare когда-то перестанет открываться).


=====================================================================
  СПОСОБ А. CLOUDFLARE WORKERS (бесплатно, без сервера)
=====================================================================

1. Зарегистрируйтесь на https://dash.cloudflare.com (бесплатно, нужна почта).

2. Слева «Compute (Workers)» / «Workers & Pages» → «Create» →
   «Start with Hello World!» → имя, например  lunka-tg  → «Deploy».

3. Нажмите «Edit code», СОТРИТЕ всё, что там есть, и вставьте:

export default {
  async fetch(request) {
    const url = new URL(request.url);
    if (!url.pathname.startsWith("/bot") && !url.pathname.startsWith("/file/bot")) {
      return new Response("not found", { status: 404 });
    }
    url.hostname = "api.telegram.org";
    return fetch(new Request(url, request));
  },
};

   Нажмите «Deploy». Скопируйте адрес вида  https://lunka-tg.ИМЯ.workers.dev

4. Проверка на российском сервере (вставьте СВОЙ адрес):

     curl -s https://lunka-tg.ИМЯ.workers.dev/bot/getMe; echo

   Должно напечатать:  {"ok":false,"error_code":404,"description":"Not Found"}
   Это ПРАВИЛЬНО — ответил сам Telegram, значит мост работает.

5. Сказать программе ходить через мост (СВОЙ адрес, без / в конце):

     echo 'TG_API=https://lunka-tg.ИМЯ.workers.dev' >> /opt/lunka/.env

   Запуск как обычно. В окне появится «Telegram работает через мост».
   Если уже настроен автозапуск:  systemctl restart lunka

   Бесплатно — до 100 000 запросов в день. Одному салону хватает с запасом;
   если салонов станет 10+ — тариф Workers Paid ($5/мес) или способ Б.
   Убрать мост: удалите строку TG_API из /opt/lunka/.env и перезапустите.


=====================================================================
  СПОСОБ Б. СВОЙ ЗАРУБЕЖНЫЙ СЕРВЕР + SSH
=====================================================================

  Российский сервер держит зашифрованное SSH-соединение с мостом.
  На мосту НИЧЕГО устанавливать не нужно — подойдёт любой самый дешёвый
  Linux-сервер за границей (Финляндия, Нидерланды, Германия, Казахстан…).

1. ВЗЯТЬ ЗАРУБЕЖНЫЙ СЕРВЕР
   Любой хостинг, самый дешёвый тариф, Ubuntu 24.04, без ПО.
   Запишите его IP и пароль root. Больше с ним ничего делать не нужно.


2. НА РОССИЙСКОМ СЕРВЕРЕ (все команды — там)

   Вместо 1.2.3.4 впишите IP ЗАРУБЕЖНОГО сервера:

     BRIDGE=1.2.3.4

   Ключ для входа на мост без пароля (просто Enter):

     ssh-keygen -t ed25519 -N "" -f /root/.ssh/bridge

   Отдать ключ мосту (спросит yes и ПАРОЛЬ ЗАРУБЕЖНОГО сервера — один раз):

     ssh-copy-id -i /root/.ssh/bridge.pub root@$BRIDGE

   Проверка — должно напечатать 302:

     ssh -i /root/.ssh/bridge root@$BRIDGE "curl -s -o /dev/null -w '%{http_code}' https://api.telegram.org"; echo


3. ВКЛЮЧИТЬ МОСТ (вставьте целиком, от cat до последней строки)

cat > /etc/systemd/system/tg-bridge.service <<EOF
[Unit]
Description=Telegram bridge
After=network-online.target
Wants=network-online.target

[Service]
ExecStart=/usr/bin/ssh -N -D 127.0.0.1:1080 -i /root/.ssh/bridge -o ServerAliveInterval=20 -o ServerAliveCountMax=3 -o ExitOnForwardFailure=yes -o StrictHostKeyChecking=accept-new root@$BRIDGE
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
EOF
systemctl daemon-reload
systemctl enable --now tg-bridge

   Проверка — должно напечатать 302:

     curl -s -x socks5h://127.0.0.1:1080 -o /dev/null -w "%{http_code}\n" https://api.telegram.org


4. СКАЗАТЬ ПРОГРАММЕ ХОДИТЬ ЧЕРЕЗ МОСТ

     echo 'TG_PROXY=socks5://127.0.0.1:1080' >> /opt/lunka/.env

   Запуск как обычно. В окне появится «Telegram работает через мост».
   Если уже настроен автозапуск:  systemctl restart lunka


ЕСЛИ ЧТО-ТО НЕ ТАК
     systemctl status tg-bridge          — работает ли мост
     journalctl -u tg-bridge -n 30       — последние сообщения моста
   • Мост упал — он сам переподключается каждые 5 секунд.
   • Зарубежный сервер пропал/заблокирован — возьмите новый и повторите
     шаги 2–3 с новым IP (шаг 4 не нужен). Данные салонов не затронуты.
   • Убрать мост: удалите строку TG_PROXY из /opt/lunka/.env
     и выполните  systemctl disable --now tg-bridge

   MAX через мост НЕ ходит — он работает напрямую с российского сервера.
